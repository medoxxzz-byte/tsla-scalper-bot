# مراجعة ترحيل المرحلة A — هوية الحدث وسجل الاستلامات

**التاريخ:** 17 سبتمبر 2026
**الحالة:** تم التحضير والاختبار على فرع Neon مؤقت ثم تطبيق الترحيل المعتمد على الفرع الحي.
**النطاق:** إصلاح هوية وموثوقية تخزين أحداث V17 وV18 فقط. لا يغير شروط الإشارات أو حدودها أو نوافذها الزمنية أو رسائل Telegram.

## ما الذي سيتغير في قاعدة البيانات الحية عند الاعتماد

يضيف الترحيل إلى `tm_research_events` حقول الهوية الرسمية `schema_version` و`signal_family` و`symbol` و`timeframe` و`bar_open_time` و`bar_close_time` و`payload_hash` و`data_quality_tier`. كما ينشئ جدول `webhook_receipts` الذي يسجل كل وصول بوصفه `new` أو `duplicate` أو `conflict` أو `invalid`، مع الحمولة الأصلية وبصمتها وسبب الرفض أو أسماء الحقول المتعارضة عند الحاجة.

لا يحذف الترحيل أي صف، ولا يعيد كتابة حمولة تاريخية. الصفوف الموجودة قبل الإصلاح تُوسم فقط بـ`pilot_pre_identity_fix`، وبالتالي تبقى قابلة للمراجعة ولا تدخل العينة العلمية الرسمية. تنشأ طبقة `official` فقط من أول تنبيه طبيعي يحمل هوية `event-v2` بعد نشر التطبيق والسكريبتين الجديدين.

يعاد إنشاء عرض `tm_research_events_session_period` ليعطي أولوية لوقت إغلاق شمعة TradingView (`bar_close_time`) للأحداث الرسمية؛ ويظل يستخدم أساسه القديم للـPilot. ويضاف عرض ملخص للاستلامات، دون إنشاء أي نتائج تداول أو متابعة سعرية جديدة.

## عقد الهوية المرسل من Pine

يرسل كل حدث جديد في V17 أو V18 الحقول التالية قبل بقية الحمولة:

```json
{
  "schema_version": "event-v2",
  "symbol": "TSLA",
  "timeframe": "1m أو 5m",
  "bar_open_time": "Unix epoch milliseconds",
  "bar_close_time": "Unix epoch milliseconds",
  "action": "اسم الإجراء الحالي كما هو"
}
```

يتكون المفتاح القانوني من الإصدار والمصدر وعائلة الإشارة والرمز والفريم ووقت إغلاق الشمعة والإجراء والاتجاه وحدود المنطقة المعيارية. **لا يدخل السعر الحالي أو CMF أو MOM في المفتاح**؛ لذلك اختلافها في إعادة إرسال بالهوية نفسها ينتج `conflict` موثقاً ولا يحوّل الحدث إلى فرصة ثانية أو يغير الأصل.

## ما ثبت على الفرع المؤقت

| اختبار | النتيجة المطلوبة | النتيجة |
|---|---|---|
| حمولة صحيحة | حدث قانوني واحد + receipt `new` | نجح |
| إعادة مطابقة | لا حدث جديد + receipt `duplicate` | نجح |
| تعارض CMF/MOM | الأصل ثابت + receipt `conflict` | نجح |
| هوية ناقصة | لا حدث قانوني + receipt `invalid` | نجح |
| إرسالان متزامنان | حدث واحد + سجلّا استلام | نجح |
| Pilot تاريخي | يبقى دون زمن شمعة ويُعزل | نجح |
| تصنيف زمن الجلسة | يستخدم `bar_close_time` للأحداث الجديدة | نجح |
| اختبارات الوحدة | 9 اختبارات هوية وبصمة | نجحت |

## المتبقي بعد اعتماد Neon ونشر التطبيق

لا يزال يلزم تنفيذ اختباري الإنتاج الآمنين: إعادة تشغيل Render ثم إعادة إرسال حمولة اختبارية رسمية للتأكد من أن النتيجة `duplicate`، ومحاكاة فشل Telegram داخل harness مع التأكد أن التخزين بقي ناجحاً. ثم تتحدث النسخة اليومية والاستعادة لتشمل `webhook_receipts` والعروض الجديدة. لا تُعلن العينة الرسمية قبل اكتمال هذه الاختبارات وظهور أول حدث طبيعي من TradingView بهوية `event-v2`.
